**Yes — Linear can "see" your Git repo very effectively, but only if it's on GitHub (or GitLab).**

### What Linear Can See / Do with a GitHub Repo

Once you connect your GitHub repo to Linear, it gets **strong bidirectional visibility**:

*   **Pull Requests** — Linear automatically links PRs to issues (via branch names like COD-42-fix-audio or manual linking). You can see PR status, reviews, and files directly in Linear issues.
*   **Commits** — Linear detects commits that reference issue keys (e.g. Relapse-15 improve usb reset) and shows them in the issue timeline.
*   **Status Sync** — Issues can automatically move from "In Progress" → "Done" when the linked PR is merged.
*   **Comments** — Two-way syncing (comments in Linear can appear in GitHub PRs and vice versa, depending on settings).
*   **Branch Creation** — You can create a GitHub branch directly from a Linear issue with one click.
*   **Multiple Repos** — You can connect several repos to the same Linear workspace.

This is one of Linear’s strongest features — it turns your GitHub repo into a living extension of the Linear project board.

### Limitations

*   Linear does **not** read the full source code or browse files like a code editor.
*   It doesn’t have native support for self-hosted Gitea (or generic git servers) — only official GitHub and GitLab integrations.
*   It “sees” activity through webhooks and references, not by constantly scanning the entire repo.

This is exactly why we switched to making **GitHub the authoritative repo** — it gives you the best of both worlds: full git control on GitHub + excellent project visibility in Linear (which I can fully manage for you).
